# UI review, 2026-11-19

Method: every screen opened in Studio Play at 1222×591 with sample data, judged with the `uxui-evaluator` principles
and the rules in [UI_DESIGN_SYSTEM.md](UI_DESIGN_SYSTEM.md) ("every screen is a real object from a 1990s workshop").
Not seen: the tire-fitting minigame (needs the full repair flow). Phones were not tested in this pass.

Score by the evaluator's rubric: **9 / 100 (poor)**. Most of that comes from two breakages and the overlaps; the
paper documents themselves are in good shape.

## Broken (fix first)

1. **`Lighting.CCTVGrade` is missing** (removed with the lighting reset). `CCTVController.Start` waits for it forever,
   and the client starts controllers one after another, so the **case file, waiting-room clock, menu and night
   notice never start**. Fix: put the ColorCorrection back (Enabled false), and make the controller not block the
   others.
2. **`DiagnosticUI.Scanner.Side` is missing** (the LED side panel). `ScannerController.render` errors on
   `device.Side.DataLed`, so a scan shows an empty screen with "SCAN COMPLETE".
3. **The work order covers the decision panel.** Both live in `WorkOrderUI` at ZIndex 1, the decision panel opens
   the clipboard (`WorkOrderController.Show`), and the clipboard is drawn on top of the NOT YET button.

## Layout

4. **The bottom-right corner is crowded.** The HANDS tool row stays on screen under every modal, and the report's
   buttons, the night notice's START button, the dialogue box and the clipboard all sit on top of it.
5. **Buttons float outside their documents.** START SHIFT and START NEXT SHIFT / OPEN CASE FILES hang below the
   paper instead of being part of it.
6. **The report and dialogue leave the top bar uncovered** (IgnoreGuiInset off), so a black strip shows above the
   dim.

## Generic look ("AI slop")

7. **Final Disposition** is three equal dark cards with coloured top bars: a web "choose a plan" pattern. It gives
   RELEASE, QUARANTINE and NOT YET the same weight, though they don't carry the same consequences. It should be an
   object: rubber stamps on the order, a key tag on a hook, or a release slip.
8. **Dialogue box** is a plain dark rectangle with an amber "CUSTOMER" label; there's no name and no object.
9. **Crew panel** is a dark card with a phone-signal icon.
10. **CCTV camera list** is four identical rounded cards with a mint fill on the selected one. It should look like
    the monitor's own channel buttons or an on-screen display.
11. **Case file tabs** look like browser tabs (three equal boxes).

## Readability

12. **The work order's text is too small.** Labels and section heads render at about 9–10 px at this window size,
    which is under the 13-px design floor. The checkbox mark reads as a broken glyph, and the CHECKED stamp overlaps
    the checklist box.
13. **The HUD's JOB / REP line is about 8 px.** The HANDS label floats above the tools.
14. **The report's row rules are uneven** (none between rows 1 and 2), and the SHIFT CLOSED stamp crowds the
    notes.
15. **The menu has no dim behind it**, so the list sits straight on the world.

## Done the same day (Play-tested at 1222×591, solo)

- **1** `Lighting.CCTVGrade` put back (Enabled false). `CCTVController` now warns and carries on when the grade is
  missing, so it can never block the other controllers again.
- **2** `Scanner.Side` rebuilt with PWR / DATA / OBD LEDs and a speaker grille.
- **3, 7** The decision is now **rubber stamps on the order**: `Clipboard.Paper.Columns.Right.Decide` holds
  `Stamps.ReleaseButton` (RELEASED, faded until the repair is checked), `Stamps.QuarantineButton` and a "Not yet"
  link (`LaterButton`, Modal). While you decide, the CHECKED stamp, Repair Tasks and Disposition rows hide
  (`Config.DECISION_HIDE`). Pressing a stamp straightens it, pushes it down with a thump (`StampSound`, PSE
  9114773735), then sends the choice. The old `WorkOrderUI.Disposition` card panel is gone.
- **4, 5** New `ShopClient.HudCover`: the HUD hides while the report, night notice, case file, menu or CCTV is open.
  Menu and CCTV now use it instead of saving `hud.Enabled` themselves.
- **6** `ShiftReportUI.IgnoreGuiInset` = true, so the dim covers the top bar.
- **8** Dialogue is now film-style subtitles: a centred name and line over a soft shade, 50 % wide (max 660), clear
  of the tool row.
- **9** The crew list is a paper roster: NIGHT CREW, "1 / 4 ON SHIFT", ink rules, status dots in ink colours. The
  signal-bars icon is gone.
- **10** CCTV camera buttons: an LED lights for the live camera, and the code turns CRT green. No more mint fill.
- **11** Case file tabs are typed labels with an ink underline on the open page.
- **12** Work order top margin 122 → 20, so the clipboard may cover the cash box while it's open. It went from
  0.68 to 0.89 scale on this window.
- **13** HUD: the JOB / REP line is 14 → 16, the shift label 14 → 15 and the tool keys 14 → 15.
- **14** Report row rules are 2 px at 0.8 transparency, so they all render. The SHIFT CLOSED stamp moved beside
  the END OF SHIFT title, and the notes column is 62 % wide.
- **15** The menu has a dark wash behind it (`PauseMenu.Dim`), stronger on the left.

Not checked on a device: phones (by maths, the stamps are about 56 px tall at the 0.72 floor; the "Not yet" link is
about 24 px, under the 44-px touch goal), gamepad selection on the stamps, and a real server decision. The press
was tested against a decision opened by hand, so the server ignored it.

## What already works

- The paper documents (work order, report, case file, night notice) read as real paperwork, with one palette and
  type system.
- The case file's pinned photo and index slips, and the report's ledger, are the strongest screens.
- The scanner uses function-key labels and has a device frame.
- The truth only appears in the report and the case file, never mid-shift.
